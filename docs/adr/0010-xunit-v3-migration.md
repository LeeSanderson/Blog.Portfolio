# Migrated the solution to xunit v3

ADR-0009 chose Verify for HTML email snapshots and recorded a caveat: `Verify.Xunit` is the xunit v2 package, was deprecated as "Legacy" in February 2026 in favour of `Verify.XunitV3`, and is frozen at 31.12.5. That caveat stopped being theoretical one ticket later. `Verify.DiffPlex` had to be held at 3.1.2 rather than the current release, because later versions require a Verify core that is binary incompatible with the frozen v2 line and fails at runtime with a `MethodAccessException` — a failure that surfaces inside the test run rather than at build time, so the pin needed a comment to stop the next person unpinning it and losing an afternoon. Every future Verify release sat behind the same wall.

Migrated all four test projects from xunit 2.9.3 to xunit v3, swapped `Verify.Xunit` for `Verify.XunitV3`, and moved `Verify.DiffPlex` up to 3.3.1. The migration was mechanical: the projects use none of the APIs that changed between the two majors — no `Xunit.Abstractions`, `ITestOutputHelper`, `IAsyncLifetime`, class or collection fixtures, or `MemberData` — so it is package references only, with no test code touched.

xunit v3 is held on the 3.x line at 3.2.2 rather than the current 4.0.0, because `Verify.XunitV3` 31.28.0 is built against `xunit.v3.extensibility.core` 3.2.2. That dependency is a NuGet minimum, not an upper bound, so 4.0.0 would resolve perfectly happily — the hold is a precaution against an untested major pairing, not avoidance of a break anyone has observed. It is worth taking because this is precisely the shape of problem that produced the DiffPlex pin: a mismatch between Verify and the test framework it adapts shows up as a runtime failure inside the suite, where it reads as baffling rather than as a version conflict. The two packages move together when Verify ships against 4.x.

The projects stay on VSTest — `Microsoft.NET.Test.Sdk` plus `xunit.runner.visualstudio`, which supports v3 — rather than moving to Microsoft.Testing.Platform. Keeping VSTest means `dotnet test`, the `coverlet.collector` coverage integration, and the CI workflow are untouched by this change; adopting the new platform is a separable decision with its own tradeoffs and no forcing reason today.

The approved snapshot files are byte-identical before and after, which is the evidence that swapping the Verify adapter changed nothing about what the builders render, and the snapshot guard was proved still live rather than assumed — a snapshot suite that had silently stopped comparing would look exactly like a green one. Ticket 06's comments record how both were checked.
