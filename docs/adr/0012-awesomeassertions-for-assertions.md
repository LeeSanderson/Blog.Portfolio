# Switched assertions from FluentAssertions to AwesomeAssertions

FluentAssertions was Apache-2.0 up to and including 7.x. The 8.0 release moved it to the Xceed Community License, which is free for non-commercial use but charges for commercial use, and this repo was on 8.10.0. AwesomeAssertions is a community fork of the 7.x line that stayed Apache-2.0 and whose maintainers have stated the licence will never change, "not even to MIT". All four test projects moved to AwesomeAssertions 9.6.0.

Whether a personal portfolio for sixsideddice.com counts as commercial use was deliberately not litigated. The value of moving is that the question stops needing an answer, and it is cheapest to move now: assertions are in nine files today and every test written from here adds to that number.

The fork descends from FluentAssertions 7.x while this repo ran 8.10.0, so API parity was checked rather than assumed. The solution's entire assertion surface is seven methods — `Be`, `BeFalse`, `BeTrue`, `StartWithEquivalentOf`, `Throw`, `NotBeEmpty` and `Contain` — all of which are stable across both lineages. That is the evidence the change was safe; without it, a future reader sees a move from an 8.x package to a fork of 7.x and reasonably wonders what was given up.

The 9.x line was chosen over 8.x even though 8.2.0 would have been a zero-source-change swap. AwesomeAssertions 9.0.0 renamed the namespace from `FluentAssertions` to `AwesomeAssertions`; the 8.x line kept the old namespace, so it would have been a package reference change and nothing else. It was rejected for two reasons. It is a superseded major line, which is exactly the trap ADR-0010 documents for the frozen `Verify.Xunit` v2 line, where a version wall cost an afternoon and needed a comment to stop the next person walking into it. And keeping `using FluentAssertions;` at the top of files that no longer depend on FluentAssertions makes the code lie about what it uses, so the fork would only be discoverable by reading a csproj. Nine compiler-verified `using` edits is a better price than either.

The evidence that this changed no behaviour is that the suite ran 29 tests green before and after, the only difference in any `.cs` file is the one `using` line, and every Verify `*.verified.html` is byte-identical — which matters because those snapshots are the only assertion in the repo over rendered email markup, and a snapshot suite that had silently stopped comparing would look exactly like a green one.

Delivered alongside the move to NSubstitute (ADR-0011) but recorded separately, because the two decisions have different drivers and will be revisited independently. This one was sequenced first: it is the purely mechanical of the two, so the mocking migration — whose only proof of faithfulness is a passing suite — had a baseline that was not moving underneath it.
