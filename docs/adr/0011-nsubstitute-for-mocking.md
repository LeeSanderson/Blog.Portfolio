# Migrated mocking from Moq to NSubstitute

Moq 4.20.72 worked and every test using it was green. NSubstitute is simply the preferred library, and the reason to act on that now rather than later is that the switching cost only grows: Moq was in five test files, and every test written between now and some future migration would have added to that number. The argument for moving was at its strongest on the day it was cheapest. All five files were translated to NSubstitute 6.2.0 and Moq was removed from the repo. This is not a judgement about Moq, and in particular not about the SponsorLink episode — 4.20.0 shipped an obfuscated dependency that hashed developers' git email addresses, but it was removed in 4.20.2 and nothing of it survived into the version in use here.

The five files were translated one construct at a time and nothing else was changed. `Times.Once` maps to `Received(1)` rather than to a bare `Received()`, which means "at least once" and would have silently weakened all twelve exact-count assertions into assertions that cannot fail for the reason they were written. The evidence that the translation was faithful is that the suite ran 29 tests green before and after, with the same test names and the same count, and that the verification profile is unchanged: twelve exact-count checks and fourteen never-checks, the same twelve and fourteen as before.

The tests were deliberately **not** restructured while they were being translated, even though the case for replacing the mocked `ISubscriberStore` and `IEmailOutbox` with hand-written in-memory fakes is a real one. Keeping the change to a translation is what makes "the suite still passes" a proof rather than a hope; the moment the arrangements are also redesigned, a translation mistake and a deliberate improvement look identical in the diff and behaviour has to be re-verified by reading rather than by running. The fakes question is recorded as its own ticket rather than left to be noticed, because this change also makes it less likely anyone would trip over it — see below.

`NSubstitute.Analyzers.CSharp` was adopted alongside the library, with its rules as errors, because it guards the one respect in which NSubstitute is genuinely more dangerous than Moq. Moq's `x => x.Method(…)` lambda is never executed, so a malformed setup is a compile error. NSubstitute's arrange and assert syntax are real method calls on a real object, so `_emailOutbox.Received(1);` — with no call after it — compiles, asserts nothing, and passes. Across 26 verification sites that is the worst available failure mode, because nothing goes red to report it. NS5000 catches exactly this, and it was proved to fire as a build error against a deliberately dangling check rather than assumed to be working.

No further guard was added against Moq returning. Central Package Management already handles the accidental case: with no `PackageVersion` entry, a `PackageReference` to Moq fails the build with NU1010. A banned-symbols analyzer or an architecture test would only catch the deliberate case, which is a decision someone would be making on purpose, and this is the right place to argue with that decision. This is a different judgement from the route-prefix architecture test in `host/tests`, which earns its keep because a wrong route is invisible in review until it is deployed; a package reference is a line in a csproj diff.

Mocking is in 5 of 12 test files, so both libraries stay as per-file `using` directives rather than becoming a global using in the csproj. `<Using Include="Xunit" />` is justified because `[Fact]` is in every test file without exception, so making it implicit costs no information. `using NSubstitute;` at the top of a file is signal worth keeping: it says at a glance that this test substitutes something, and its absence from `HmacSubscriberTokenServiceTests` says that one does not.

The `tdd` skill's guidance was corrected as part of this, because the migration made a latent contradiction newly visible: `mocking.md` said "don't mock your own classes", while every interface mocked here is one this repo declares. The tension was only apparent — `ISubscriberStore` is a port over Azure Table Storage, `IEmailOutbox` over Azure Queue Storage, `IEmailSender` over Resend, and the same document already sanctions mocking external APIs and databases — so `mocking.md` now draws that distinction explicitly: the test is whether a real call leaves the process, not whether you declared the interface. Without that, an agent reading the guidance and then reading these freshly-rewritten tests would have had documented licence to "fix" tests that are fine.

Note that the `tdd` skill is vendored from `mattpocock/skills` and tracked by a `computedHash` in `skills-lock.json`, so these edits are a local divergence from upstream and a future skills sync may silently revert them. That was accepted knowingly: the alternative was to put project-specific guidance only in `CODING_STANDARDS.md` and leave a stale Moq sample in the file agents actually read before writing a test. If the sync does revert it, this paragraph is the record of what to put back.

One case the reconciliation does not rescue: `SendEmailFunctionTests` is a single test over a single-line pass-through function, asserting that a delegation happened, named after the mechanism rather than the behaviour. Measured against the `tdd` skill's own red flags it is the anti-pattern, no clarifying passage about ports changes that, and it was translated as-is only because this change was scoped as a translation. It is named in the follow-up ticket so that it gets an answer rather than an inheritance.
