# Verify for HTML email snapshot tests

The two emails this portfolio sends — the confirmation email and the Digest — had untested bodies and no artifact anywhere in the repo showing what a Subscriber actually receives. Fixing that means comparing rendered HTML against an approved copy committed beside its test. We chose [Verify](https://github.com/VerifyTests/Verify) (`Verify.Xunit` plus `Verify.DiffPlex`, both MIT) to own that comparison, verifying the HTML body alone to a `.verified.html` file so the approved artifact is a real email that opens in a browser and diffs readably in review.

The alternative was a hand-rolled comparison: read an expected file, assert equality, write the actual on failure. It looks like a dozen lines, but the accept workflow, the received-file lifecycle, cross-platform line-ending normalization, and a guard against silently auto-approving on CI are all things we would then own and get wrong, for no benefit over a maintained library that already does them. Verify's normalization was proven here rather than assumed — an approved file passes against output whose newlines differ from it in both directions, which matters because this repo has `core.autocrlf=true` and the HTML comes from raw string literals, so a Windows working tree emits CRLF while the Linux CI runner emits LF. A `.gitattributes` rule additionally pins `*.verified.html` to LF so the committed bytes are the same on both.

Verify's diff-tool launcher is disabled and DiffPlex enabled via a module initializer in the test project, so a failure prints an inline textual diff and no run opens a GUI window. That is decided for the agents that run this suite unattended: an agent can read console output but cannot see or dismiss a diff window.

Two caveats are worth recording. First, this ADR sits below the usual bar for one in this repo — the choice is cheaply reversible, so it would ordinarily just be made — but the tool choice was wanted in writing. Second, `Verify.Xunit` is the xunit v2 package and was deprecated as "Legacy" in February 2026 in favour of `Verify.XunitV3`; it is frozen at 31.12.5 while Verify's core package continues to release. It still works, but it will not receive updates, and `Verify.DiffPlex` is consequently held at 3.1.2 because later releases require a core version that is binary incompatible with that frozen line. Moving off it means migrating the whole solution to xunit v3, which is deliberately not bundled into the change that introduced snapshots.

## Amendment: the xunit v2 caveat is spent — the solution moved to xunit v3

The second caveat above has lapsed. The solution migrated to xunit v3 (ADR-0010), so this ADR's package names are now `Verify.XunitV3` rather than `Verify.Xunit`, and `Verify.DiffPlex` is on 3.3.1 rather than held at 3.1.2. Everything this ADR actually decided still stands — Verify over a hand-rolled comparison, the HTML body verified alone to a browser-openable `.verified.html` beside its test, and the disabled diff-tool launcher with DiffPlex printing inline. Only the two sentences describing the frozen v2 package and the consequent DiffPlex pin are now history.
